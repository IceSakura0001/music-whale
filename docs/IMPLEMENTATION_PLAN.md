# 计划与实施方案

## 产品目标

“点一下有音符，拖一下改旋律，按播放能合奏”。默认展示一个可以播放的四轨原创示例，避免空白工作台。复杂音色参数集中到可折叠的右侧。无需前端依赖安装，不要求用户懂代码。

## 第一阶段：可用的编曲工具（本版）

1. **项目模型**：统一拍数/MIDI 音高/力度、音轨与合成参数，所有入口复用验证和动作事务。
2. **交互**：钢琴卷帘、六行鼓机、轨道总览、拖放/拉伸/多选/复制/删除/撤销、移动端项目菜单与音色抽屉。
3. **声音**：19 个内置预设（含 FluidR3 GM 采样）与可保存的自定义合成音色，支持 16 阶泛音自定义与实测音色参数（非谐性、泛音阻尼、亮度包络、起音噪声、琴体共振、揉弦、齐奏失谐）；同一单音渲染器用于浏览器 AudioBuffer 和离线混音，提前缓存常用音符降低首次调度抖动。
4. **混音与播放**：音量/声像/静音/独奏、BPM/TAP/节拍器/循环/摇摆、总音量与空间效果。
5. **保存与导出**：私有云 R2 或本机文件保存，导入导出项目，WAV 与 MIDI，本机恢复副本。
6. **Agent**：REST、浏览器 API、8 个 MCP 工具，HTTP/stdio，版本冲突保护、原子批量编辑、浏览器播放回执。
7. **验证与交付**：数据操作、音频频率与文件格式、MIDI 信息、MCP 错误与事务测试；真实浏览器交互；私有部署与完整源码。

## 架构

`src/core.js` 为项目与操作层；`src/audio.js` 为确定性音源、WAV 和 MIDI；`src/service.js` 为 HTTP/MCP 和事务边界；`web/` 为界面及实时调度器。本机 `server.mjs` 使用文件持久化，按请求队列串行写入；云端 `worker/handler.js` 使用 R2 ETag 条件更新。构建把代码与网页资源合为无外部运行依赖的 Worker。

MCP、HTTP 与 UI 共用动作语义，不需要通过坐标来编曲。端点返回结构化项目和工具输入 Schema，方便后续 agent 扩展。

## 后续扩展（未包含在本版，不代表已完成）

1. **更真实的乐器**：带许可来源的采样器、用户上传采样、SoundFont、多采样力度层；先验证首音加载时间和缓存大小。
2. **更长的作品**：片段/场景/段落重复、可变拍号、速度自动化、钢琴踏板、和弦/音阶辅助、更多小节；先迁移 schemaVersion 并保持旧项目可导入。
3. **制作工作流**：Web MIDI 键盘录入、音频轨、录音、效果自动化、分轨批量导出、MP3；先明确浏览器兼容性与编码许可。
4. **项目库与协作**：多项目列表、历史版本、角色权限、分享、实时协作；先增加用户/项目隔离，再开放访问。
5. **Agent 深度支持**：作曲任务队列、离线高密度渲染工作进程、细粒度命令事件订阅与可取消任务。保持工具成功状态可验证。

下一版优先推荐采样音源与片段编排；它们分别改善乐器真实感和长曲创作效率。
